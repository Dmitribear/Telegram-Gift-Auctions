## Архитектура аукциона

- **Веб-API**: Express (`src/index.ts`) с маршрутами `/api/*`. Логика вынесена в сервисы (`src/services`) и репозитории (`src/repositories`).
- **MongoDB (ACID)**: все денежные операции и ставки идут через `mongoose.startSession().withTransaction(...)` с `readConcern: snapshot` и `writeConcern: majority`. Требуется replica set (см. `docker-compose.yml` с `--replSet rs0`).
- **Redis + Redlock**: перед началом транзакции берём распределённую блокировку `locks:auction:{id}` (см. `BidService`). Это защищает от гонок при одновременных ставках.
- **Анти-снайпинг**: поля аукциона `antiSnipeWindowMs` и `antiSnipeExtensionMs`. Если ставка сделана в окне до окончания, дедлайн двигается вперёд на заданное расширение.
- **Фиксация победителя**: по истечении таймера или при ручном вызове `/finalize` статус становится `ended`, сохраняется победитель и ставка в `Winner`. Повторная фиксация невозможна (idempotent).
- **Статусы**: `scheduled` (старт в будущем), `active`, `ended`. При первом хите после времени старта статус обновляется на `active`.
- **Модели**: `User`, `Auction`, `Bid`, `BalanceLedger` (лог баланса), `Winner`. См. `docs/data-models.md` для полей.

### Жизненный цикл (фазы)
1. **Старт**: создаётся аукцион с `startPrice`, `bidStep`, базовым таймером (`baseDurationMinutes`). Если `startTime` в будущем → `scheduled`.
2. **Активные ставки**: любая валидная ставка повышает `currentPrice` минимум на `bidStep`.
3. **Анти-снайпинг**: если до дедлайна меньше `antiSnipeWindowMs`, то `endTime` сдвигается на `antiSnipeExtensionMs`. Повторяется неограниченно.
4. **Завершение**: когда `endTime <= now` и нет новых ставок — статус `ended`, фиксируется победитель (если были ставки).

### Потоки данных
- **Создание аукциона** → запись в Mongo (без транзакции, один документ).
- **Депозит** → транзакция: инкремент баланса пользователя + запись в `BalanceLedger`.
- **Ставка** → Redlock → транзакция: валидация статуса и баланса, создание `Bid`, обновление `Auction` (цена, лидер, дедлайн), лог в `BalanceLedger`.
- **Финализация** → транзакция: статус `ended`, фиксация `winnerUserId/winnerBidId`, upsert в коллекцию `Winner`.
